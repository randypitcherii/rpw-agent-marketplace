Five steps from a merged PR to a published plugin

Follow the bottom line of each step: nothing reaches the public mirror until a human promotes it.

Phase 1 · automatic on every merge to production
Phase 2 · you promote
Phase 3 · the public mirror
1

Squash-merge the PR

  • One commit per PR on production
  • CI already green on the PR
Nothing published
2

Auto-bump versions

  • Marketplace + plugin versions to YYYY.MM.DDNN
  • Pushed back as its own commit
Nothing published
3

Build the target

  • Include-list copies file contents only
  • Private plugin excluded structurally
Nothing published
4

Promote

  • You run make publish-promote
  • Opens a PR on the mirror; you merge it
Mirror PR open
5

Public mirror

  • Consumers install from here
  • Release notes drafted, published by hand
Live
Always on — true at every step above

What never crosses

  • Private refs, commits, history, remotes
  • Commit messages and metadata
  • Anything under plugins/rpw-private

Where the gate lives

  • Publishing is per-target promotion, never a side effect
  • There is no implicit “publish all”

How you know it worked

  • The mirror PR diff is file contents only
  • A tagged release on production matches the bump
